<result>## 1. UserPromptSubmit hooks
Yes — output `hookSpecificOutput.additionalContext` is injected and visible to the model for that same turn (source: [Hooks reference](https://code.claude.com/docs/en/hooks)):
```json
{ "hookSpecificOutput": { "hookEventName": "UserPromptSubmit", "additionalContext": "..." }, "systemMessage": "..." }
```
Default timeout for `UserPromptSubmit` is 30s (no documented hard max, configurable via the hook's `timeout` field). Exit 0: stdout/JSON context is added, prompt proceeds. Exit 2: blocking — the prompt is rejected, stderr shown to the user, nothing goes to the model. Any other non-zero: non-blocking — prompt still goes through unchanged, transcript shows a "hook error" notice. `async: true` is supported, but async hooks aren't timeout-enforced and, since they run outside the synchronous pre-processing step, cannot affect the current turn — only future ones (`UserPromptSubmit` also doesn't support `asyncRewake`).

## 2. Changing the main session's model per message
No. Per [Model configuration](https://code.claude.com/docs/en/model-config), the main session's model is a session-level setting only changeable via `/model`, `--model`/`ANTHROPIC_MODEL` at startup, or settings files (plus the unrelated safety-driven `switchModelsOnFlag` auto-fallback). No hook output field switches it. Delegating to a subagent (with its own `model` frontmatter) is the intended way to run part of the work on a cheaper model.

## 3. Plugin subagents
Per [Sub-agents](https://code.claude.com/docs/en/sub-agents) and [Plugin components](https://code.claude.com/docs/en/plugins/components): `model` accepts aliases (`sonnet`, `opus`, `haiku`, `fable`), full model IDs (e.g. `claude-sonnet-5`), or `inherit` (same model as the main conversation). Resolution order: per-invocation `model` param → agent's own `model` frontmatter → `CLAUDE_CODE_SUBAGENT_MODEL` env var → main conversation's model. A plugin agent at `agents/security-reviewer.md` in plugin `my-plugin` is named `my-plugin:security-reviewer`, invoked as `@agent-my-plugin:security-reviewer`; subfolders add colon segments (`agents/review/security.md` → `my-plugin:review:security`). The subagent's system prompt is just its own frontmatter body plus basic env details — it is **not** told which model it's running on unless you add that manually.

## 4. Plugin slash commands
Per [Slash commands](https://code.claude.com/docs/en/slash-commands) and [Plugin components](https://code.claude.com/docs/en/plugins/components): `commands/&lt;name&gt;.md` in plugin `my-plugin` becomes `/my-plugin:&lt;name&gt;` (subfolders add colon segments, e.g. `commands/db/migrate.md` → `/my-plugin:db:migrate`); the bare `/&lt;name&gt;` also works unless another command claims that name. `$ARGUMENTS` expands to the entire typed argument string; `$0`/`$1`/... or `$ARGUMENTS[N]` give positional args; a frontmatter `arguments:` list enables named `$param` placeholders.

## 5. Plugin hooks
Per [Plugin components](https://code.claude.com/docs/en/plugins/components): `hooks/hooks.json` uses the same shape as the `hooks` key in `settings.json` (event → matcher → `hooks: [{type:"command", command:"..."}]`). Every hook process gets `CLAUDE_PLUGIN_ROOT` (versioned install dir, don't write state there) **and `CLAUDE_PLUGIN_DATA`** (persists across updates, resolves to `~/.claude/plugins/data/&lt;id&gt;/`) in its environment, plus `CLAUDE_PLUGIN_OPTION_&lt;KEY&gt;` per user-config value.

## 6. UserPromptSubmit stdin JSON
Per [Hooks reference](https://code.claude.com/docs/en/hooks): `session_id`, `prompt_id`, `transcript_path`, `cwd`, `scratchpad_dir`, `permission_mode`, `hook_event_name: "UserPromptSubmit"`, `prompt`.</result>

<result>Based on Claude Code v2.1.283 and the current documentation, here are the mechanisms for model and thinking-effort control mid-turn:

## 1. **PreToolUse Hooks on Agent/Task Tool**
Cannot modify subagent spawn parameters. `hookSpecificOutput.updatedInput` cannot rewrite `model`, `subagent_type`, or `task` — the hook can only validate and block (exit code 2), not modify. There is no `thinking` or `effort` parameter on the Agent or Task tool itself; effort is session-level only.

**Reference:** https://code.claude.com/docs/en/hooks.md confirms PreToolUse hooks cannot change agent spawn parameters.

## 2. **Hook Events for Model/Effort Changes**
No hook event can change the main session's model or effort mid-turn. PreToolUse, PostToolUse, Stop, SubagentStop, SessionStart, PreCompact, UserPromptSubmit, PreModelSwitch, and PostModelSwitch are all **read-only** or **block-only** for model decisions. PreModelSwitch can block an explicit model switch but cannot initiate or target a new model.

## 3. **Built-in Model-Split Mechanisms**

| Mechanism | What it does |
|-----------|-------------|
| `opusplan` | Model alias (e.g., `/model opusplan` or `opusplan[1m]`); uses Opus with planning capabilities |
| `CLAUDE_CODE_SUBAGENT_MODEL` | Sets default subagent model; can be overridden per spawn or per agent frontmatter |

| `ANTHROPIC_SMALL_FAST_MODEL` | Haiku used for background async work (compaction, `/recap`, naming); falls back to main model if unset or unavailable |
| **Subagent frontmatter** | `model: &lt;alias or id&gt;` and `effort: &lt;level&gt;` per agent definition |

Yes, custom base URL works with subscription OAuth login. The credential precedence puts OAuth at rank 7, below API keys and `apiKeyHelper` but above profiles. When OAuth credentials exist and no higher-priority credential is set, Claude Code sends OAuth tokens through the custom base URL.

**Subagent spawn**: opencode's built-in tool is literally named `task` (input fields `subagent_type`, `description` — confirmed via strings in the compiled binary, e.g. `Dt(t){...t.input.subagent_type...Task}`). `tool.execute.before` fires with `{tool, sessionID, callID}` and mutable `output.args`, generically for every tool call including `task`, so a plugin can rewrite `args.subagent_type` to redirect a spawn to a different (differently-modeled) agent — but it can't set a model directly on that call since `task` takes no model arg.

## Codex

`codex features list` confirms `hooks stable true`. `codex app-server generate-json-schema` output's `HookEventName` enum (`v2/HooksListResponse.json`): `preToolUse, permissionRequest, postToolUse, preCompact, postCompact, sessionStart, sessionEnd, userPromptSubmit, subagentStart, subagentStop, stop, interrupt` — subagent spawn is its own dedicated event, not routed through `preToolUse`. `HookOutputEntryKind` (`v2/HookStartedNotification.json`) is only `warning, stop, feedback, context, error` — no field for rewriting arguments, so no hook (including `subagentStart`) can rewrite model/reasoning_effort by itself.

Per-turn model/effort override does exist at the protocol level: `v2/TurnStartParams.json` has `model` and `effort` (`ReasoningEffort`) fields ("Override the reasoning effort for this turn and subsequent turns"), plus `TurnSettingsUpdateParams`. That's an app-server API a client/IDE can call, not something exposed to a `command`-type hook script.
