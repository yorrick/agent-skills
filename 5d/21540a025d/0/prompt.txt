## 2. Source verification (openai/codex main, via `gh api` code search + raw file reads)

- **The `plugins-marketplace-auto-upgrade` thread exists.** `codex-rs/core-plugins/src/manager.rs`, in `maybe_start_plugin_startup_tasks_for_config` (~line 2099–2160): inside `if config.plugins_enabled { ... }` it spawns `std::thread::Builder::new().name("plugins-marketplace-auto-upgrade".to_string())` which calls `upgrade_configured_marketplaces_for_config(&amp;config, None)` — i.e. all configured git marketplaces. **Gating: only `plugins_enabled` plus an in-flight dedup guard. No dedicated on/off config flag.**
- `plugins_enabled` = `Feature::Plugins`, key `"plugins"`, `Stage::Stable`, `default_enabled: true` (`codex-rs/features/src/lib.rs` ~line 1181). So the only lever is `[features] plugins = false` (or `--disable plugins`), which kills plugins entirely.
- **"Force-reinstall" is slightly overstated — it is revision-checked.** `codex-rs/core-plugins/src/marketplace_upgrade.rs` (`upgrade_configured_git_marketplace`, ~line 202): each startup runs `git_remote_revision` (ls-remote, 30s timeout); if `last_revision` matches the remote and installed metadata matches, it returns `Ok(None)` (no-op). Otherwise it clones to a staging dir, validates, atomically swaps the marketplace root, updates `config.toml` (`last_revision`/`last_updated`), and the manager then refreshes the installed-plugin cache. Net effect: any push to the marketplace branch lands automatically on next startup, unprompted, with no throttle interval.
- **Who triggers it:** `codex-rs/app-server/src/message_processor.rs` (~line 453) when `PluginStartupTasks::Start`. `Start` is the default (`app-server/src/lib.rs` ~line 450); `Skip` exists only behind `#[cfg(debug_assertions)]` for tests (`app-server/src/main.rs` ~line 94). Crucially, the TUI (`codex` interactive) and `codex exec` now run an **in-process app-server** (`codex-rs/tui/src/lib.rs` uses `InProcessAppServerClient`; `codex-rs/app-server/src/in_process.rs` line 476 hardcodes `PluginStartupTasks::Start`). So **both the CLI and the desktop app run the auto-upgrade at startup** — behavior does not materially differ between them.
- **`check_for_update_on_startup` is real but unrelated to plugins.** `codex-rs/config/src/config_toml.rs` ~line 470: *"When `true`, checks for Codex updates on startup and surfaces update prompts. Set to `false` only if your Codex updates are centrally managed. Defaults to `true`."* It gates the CLI self-update prompt (`codex-rs/tui/src/updates.rs` line 28) — never referenced in the plugin/marketplace upgrade path. Per #18543 the desktop app ignores it even for app updates.

## 4. Bottom line

- (a) **Yes** — at every app-server startup (desktop app, IDE, and the CLI TUI/exec via in-process app-server), Codex silently checks each configured git marketplace's remote revision and, if it moved, reinstalls the marketplace snapshot and refreshes the plugin cache. No prompt, no throttle.
- (b) **No dedicated off switch.** Only `features.plugins = false` (default true, disables plugins wholesale) or removing the git marketplace. `check_for_update_on_startup` does NOT affect it.
- (c) `check_for_update_on_startup` (default `true`) governs only Codex self-update prompts in the CLI; #18543 shows the desktop app ignores it even there (closed as not planned).
- (d) CLI vs desktop: same plugin auto-upgrade behavior (shared app-server code path). The one difference is self-updates: the CLI honors `check_for_update_on_startup` for its prompt; the desktop app's updater does not.
